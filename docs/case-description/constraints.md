# Ограничения

> [!warning] 1. Тема трека
> Решение должно соответствовать тематике трека «Досуг и развлечения» и решать обозначенную вами задачу или проблему в сфере досуга и развлечений. Актуальность задачи или проблемы должна быть обоснована.

> [!warning] 2. MAX как среда реализации
> Мессенджер MAX должен использоваться как среда реализации и/или взаимодействия с продуктом. Основной пользовательский сценарий должен быть доступен для проверки в MAX.

> [!warning] 3. Мобильная и веб-версия
> Для разработки решения может использоваться как мобильная версия MAX, так и веб-версия. При этом функциональность проекта должна быть доступна пользователям в обеих версиях платформы.

> [!info] 4. Стек
> Для работы с мессенджером MAX советуем использовать JavaScript и React. Допускается использование других языков программирования и API.

> [!warning] 5. Форма решения
> Решение может быть реализовано:
> - как чат-бот;
> - как чат-бот с подключенным мини-приложением.
>
> Мини-приложение в MAX подключается к чат-боту и не используется как изолированный от него сервис.

> [!info] 6. Собственный API
> Наличие собственного API не обязательно и само по себе не дает дополнительных баллов.

> [!danger] 7. Закрытый код и частные API
> Запрещено использование закрытых библиотек, частных API и чужого кода, не подпадающего под разрешение о свободном распространении и использовании.

> [!danger] 8. Секреты
> Нельзя размещать в репозитории рабочие токены, пароли, API-ключи и другие секреты.

> [!warning] 9. Законодательство и правила
> Необходимо соблюдать российское законодательство, актуальные [правила платформы MAX](https://legal.max.ru/ps), а также правила хакатона, доступ к которым предоставлен на [официальном сайте проекта](https://hackathon-max.vk.company/).

> [!info] 10. Тестовые данные вместо реальной интеграции
> Если в MVP вместо реального подключения к внешней информационной системе используются тестовые, заранее подготовленные или смоделированные данные, это должно быть явно указано в материалах.

> [!warning] 11. Ник чат-бота
> Учитывайте ограничения платформы при создании чат-бота: после его создания ник чат-бота изменить нельзя.

> [!warning] 12. Версия после дедлайна
> После дедлайна переданная версия исходного кода не изменяется.
