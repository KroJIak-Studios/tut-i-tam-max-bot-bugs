# Тестовые данные для технической проверки «Тут и там»

Секретов здесь нет. Пароль администратора, токен бота и контрольное слово передаются отдельно.

## Пользователь мини-приложения

Роль `user` из `DATA-API.yaml`.

```http
Authorization: tma local-development:910001:Jury:ru-ru
Host: localhost
```

Заголовок работает, когда в `.env` стоит `LOCAL_DEV_AUTH_ENABLED=true`, а запрос приходит на `localhost` или `127.0.0.1`. Пользователь создаётся при первом запросе. Город подставляется ближайший из справочника — в демо-данных это Казань.

Второй пользователь для проверки «чужого» мероприятия:

```http
Authorization: tma local-development:910002:Guest:ru-ru
```

## Администратор

Админ-панель: `http://localhost:8080`.

Пароль — значение `ADMIN_PASSWORD` из `.env`. Его нет в репозитории.

## Точка «рядом»

```json
{
  "latitude": 55.796,
  "longitude": 49.106
}
```

Это центр Казани у Кремля. `POST /api/recommendations/app/nearby` возвращает ближайшее видимое мероприятие из демо-каталога.

## Своё мероприятие

```json
{
  "title": "Прогулка для технической проверки",
  "description": "Событие создано автоматической проверкой и будет удалено.",
  "city_id": 1,
  "address": "Казанский Кремль",
  "latitude": 55.798,
  "longitude": 49.105,
  "starts_at": "2026-10-20T12:00:00+03:00",
  "ends_at": "2026-10-20T14:00:00+03:00"
}
```

`city_id` берите из `GET /api/v1/cities`: в чистой базе первый город — Казань.

## Ссылка чата

Принимается:

```text
https://max.ru/join/jury-check-tut-i-tam
```

Отклоняется с `422` и `invalid_chat_link`:

```text
https://example.com/not-an-invite
```

Одна ссылка-приглашение принадлежит одному мероприятию. Повторная привязка к тому же мероприятию проходит. Привязка к другому мероприятию возвращает `409` и `chat_already_used`.
